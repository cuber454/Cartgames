# Концепция: доступные карточные игры для Android

Черновик v0.2 · для Странника

## 1. Что это

Android-приложение с карточными играми, сделанное так, чтобы в него
полноценно могли играть незрячие и слабовидящие люди — без опоры на
изображение. Одно приложение-«платформа», внутри которого несколько игр,
добавляемых по шаблону.

Ключевая мысль: в карточных играх никто не видит чужих карт, поэтому
незрячий игрок здесь почти в равных условиях. Всё, что нужно, — чтобы
приложение **проговаривало** состояние игры и принимало команды.

## 2. Версия Android — решено

Целимся в **Android 16** (свежая система). Минимальная версия —
**minSdk 24 (Android 7)**: покрытие почти 100% устройств, все современные
библиотеки доступны. Ставить минимум на уровне «только Android 16» смысла
нет — отрежет старые телефоны без выигрыша.

## 3. Технология — предложено

**Kotlin + Jetpack Compose.**

Почему не игровые движки (Unity, Godot): они рисуют игру как картинку на
canvas, а скринридер такую картинку не читает. Для незрячего пользователя
это тупик. Нужны настоящие элементы интерфейса со словесным описанием.

- **Kotlin + Compose** — TalkBack «из коробки», лучшая озвучка. Рекомендую.
- **Flutter** — если позже захочется iOS; доступность хорошая, но
  TalkBack-семантику настраивать сложнее.
- **Unity / Godot** — не подходят: доступность слабая.

## 4. Архитектура: одно ядро, много игр

Три слоя, независимых друг от друга:

1. **Ядро (движок).** Колода, раздача, очередь хода, проверка
   «можно/нельзя», подсчёт, история событий. Про конкретные игры не знает.
2. **Правила игр.** Каждая игра — отдельный модуль по общему шаблону.
3. **Слой доступности.** Превращает события ядра в речь, звук, вибрацию.
   Один на все игры — поэтому новая игра не требует новой озвучки.

**Ответ на «как добавлять игры»:** делаем один раз шаблон (контракт), по
которому описывается любая карточная игра. Новая игра = новый файл,
заполненный по шаблону. Интерфейс, озвучка, звуки, TalkBack — общие.

### Шаблон игры — что в нём описывается

- как собирается колода и сколько карт раздаётся;
- какие ходы допустимы сейчас (это главный метод);
- что происходит после хода — кто ходит дальше, куда уходят карты;
- как словами объявить событие («Петя взял две карты»);
- когда игра закончена и кто выиграл.

### Роль нейросети

Да, именно так: ты говоришь «хочу такую-то игру» — нейросеть (я или
дипсик) пишет файл правил по шаблону, мы проверяем, и игра появляется.
Для простых игр это почти целиком данные, для сложных — данные плюс
небольшая логика. От человека — только проверка и тесты.

## 5. Требования доступности (обязательные)

- **Полная озвучка.** Каждое событие словами.
- **TalkBack.** У каждого элемента словесное описание
  (`contentDescription`), логичный порядок фокуса, принудительное
  объявление важных событий.
- **Управление без взгляда.** Крупные зоны нажатия, свайпы, голосовые
  команды: «бить семёркой червей», «взять», «перевести», «что на столе»,
  «повтори».
- **Звук и вибрация.** Разные сигналы на свой ход, чужой ход, ошибку,
  победу.
- **Настройки.** Скорость речи, подробность озвучки, громкость,
  «сколько карт у соперника».
- **Для слабовидящих.** Крупный шрифт, высокий контраст, тёмная тема,
  различимость не только по цвету.

## 6. Игры и порядок

Первая игра — **«Дурак»** (решено). «Тысяча» — следующая. «Пьяницы» не
будет. Пасьянс делаем параллельно с «Дураком» — отдельным движком
(раскладки одиночные, механика другая). «Э…» из списка оказалось опечаткой
голосового ввода — такой игры нет.

Порядок: ядро + «Дурак» → «Тысяча» → остальные по шаблону.

## 7. Этапы

- **Этап 0 (MVP).** Каркас приложения, ядро, «Дурак»: ты против простого
  бота. Полная озвучка и TalkBack. Цель — доказать, что играть вслепую
  реально.
- **Этап 1.** Оформляем шаблон игры; добавляем «Тысячу» по нему, не
  трогая интерфейс и озвучку.
- **Этап 2.** Голосовые команды, звуки, вибрация, настройки, выбор голоса
  озвучки (в том числе из установленных на телефоне TTS-движков).
- **Этап 3.** Игра вдвоём на одном устройстве, затем по сети.

## 8. Сборка

Код живёт на GitHub, APK собирается автоматически через GitHub Actions —
как ты и хотел. Получаешь готовый файл по каждой сборке.

## 9. Открытые вопросы

1. Репозиторий на GitHub — создаём? Это главный блокер: без него нет ни
   сборки, ни прогона тестов.
2. Название проекта: оставляем «карточные игры» или переименовываем — внутри
   появился ещё и помощник (см. §10).
3. Помощник: вибрация при подъёме — один раз или повторять, пока не
   разблокируешь? Второе полезнее, но настойчивее.

## 10. Помощник: функции вне игр (обсуждается)

Странник предложил расширить приложение за пределы игр. Первая такая
функция — вибронапоминание о пропущенном звонке при подъёме телефона:
телефон лежит заблокированный, ты его поднимаешь, и если кто-то звонил —
короткая вибрация. Экран не загорается, разблокировка не нужна.

Как это устроено: фоновая служба ловит движение, приложение знает о
пропущенном звонке, при подъёме подаёт вибрацию.

Технические заметки:

- Пропущенные звонки — либо журнал звонков (просто и надёжно), либо
  прослушивание уведомлений (ловит ещё WhatsApp, Telegram, Skype — у
  незрячих половина звонков идёт оттуда). Рекомендую второе, первое как
  подстраховка.
- Android 14+ требует объявленный тип фоновой службы. Для датчиков движения
  подходит `specialUse` (`FOREGROUND_SERVICE_SPECIAL_USE`) — у него нет
  runtime-разрешений. Плюс разрешение на распознавание активности.
- Doze (глубокий сон) вибрацию не запрещает, но момент срабатывания нужно
  проверять на живом устройстве: прошивки Samsung и Xiaomi агрессивно душат
  фон, и на телефоне поведение может отличаться от документации.
- У многих прошивок уже есть готовое «напоминание об уведомлениях» по
  таймеру — проверить до того, как строить своё.

Предложение по порядку: сделать эту функцию **до** «Дурака». Она маленькая,
польза немедленная, и на ней проверяется весь путь «код → автосборка → APK →
установка на телефон», пока правила игры ещё не усложняют отладку.

Структура при этом: одна программа, два раздела — «игры» и «помощник», общий
слой доступности (озвучка, жесты, настройки, вибрация) один на всех. Два
отдельных приложения не нужны.
